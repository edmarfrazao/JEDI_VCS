## What's new

### The 2026 `jvcs.exe` console is now in the installer
The installer now ships the new console, with about 50 commands. The old commands work as before, and the server is
still the unchanged 2.5 Beta 3.

- **Projects and modules without the IDE:** `addproject`, `addmodule` (also stores the local folder) and
  `setmodulepath`. `checkin` does the first check-in (0.1) of a new module and sends its family (a unit's `.dfm`),
  like the standalone client.
- **History and search:** `history` (revisions with date, user and comment), `projectlog` (project check-ins from
  the server log), `searchmodules` and `searchcomments`.
- **Server features:** labels, shared modules, ToDo, milestones and bugs (list, create, update, link to modules).
- **Administration:** list, remove, rename and hide modules; change a revision comment; remove, restore and rename
  projects. Commands that delete things require the word `confirm`.
- **State by date and Put:** `projectrevs` (project revisions by date) and `checkin ... keep` (new revision, the
  module stays checked out).
- **Fixes:** `getmodule` accepts `rev=` + `dest=` + `noprompt` together (an original bug); commands accept the short
  name of a module that has a stored folder; a check-in refused by the server is now an error with the reason
  instead of passing silently.
- **Review of Oct 17:**
  - `addmodule` no longer creates a duplicate module when the file already is a module (folder in its long or 8.3
    form);
  - a refused first check-in, an existing project and a folder that was not stored no longer print the help with
    exit code 0;
  - the `/input` file is read in cp1252 whatever the Windows code page is (with "UTF-8 beta" accents arrived
    garbled);
  - `removemodule ... archive`, which deletes the module and its revisions, now requires the word `confirm`.

### AI automation: `jvcs-ai.ps1` wrapper 1.4.0
Since Beta 5 the wrapper used by Claude Code gained:

- `diff` against the server revision or between two revisions, `show -Rev` (an old revision in a reference folder)
  and `history`;
- `addproject` and `add` (register and first check-in without the IDE);
- `sync`: a preview of what changes, and `-Apply` with a backup. It never touches the user's check-outs.
  `sync -Label` and `sync -Date` bring the local copy back to a label or a date; `sync -Dest` exports the state to a
  new folder;
- `changes` (what changed in the project since a date), `search` (modules, or text in comments), `labels`/`label`,
  `shared`, `todo`, `milestones` and `bugs`;
- `blame` (who changed each line), `revert -Rev` (go back to a revision, with a backup) and a build before check-in
  (`buildCheck`, only with the script the user registered);
- module and project administration. It always shows a preview, makes a backup and asks for approval, and `-Apply`
  requires `moduleAdmin`/`projectAdmin` to be on in `config.ini`;
- `checkin -Keep` (Put);
- requests from the remote PC (xHarbour sources):
  - `status` and `sync` no longer stop the whole project because of one module (exit code 11 = partial);
  - project and identity per folder, without a `.dpr` (`.jvcsproject` or maps in `config.ini`);
  - an `-Only` filter;
  - `locks` with the local state of each module;
  - batch operations with `-FromList`, with a preview and a single approval.

Commands that change the server follow the check-in mode (`manual`/`confirm`/`auto`). The pt/en skills, the settings
template 1.3.0 (with `ask` rules for administration) and the AI guides were updated. Details (Portuguese):
[`tools/ai/LEIAME.md`](../../tools/ai/LEIAME.md); English guide:
[05-Using-with-AI](../../doc/en/05-Using-with-AI.md).

### Installer: the AI uses the new console by default
- The task **"Use the new console (jvcs.exe of this installation) for the AI automation"** is now **checked**. It
  writes `jvcsExe` to `%APPDATA%\JEDI\JVCS\config.ini`. Without it, the wrapper would use the original 2.5.0.1030
  `jvcs.exe`, which lacks the new commands.
- When **upgrading** from Beta 5 or older, where the task was unchecked, it is checked once; you can uncheck it on
  the tasks page. The previous `config.ini` value is saved and comes back on uninstall, or if the task is unchecked in
  a later reinstall.

### Known issues (2.5 server)
Limitations of the 2.5 Beta 3 server, which the client works around or reports:

- a module **with revisions** cannot be deleted from the archive, only removed from the project;
- `RENAME_PROJECT` does not rename the modules (the console renames them one by one);
- a label is not moved to another revision.

Full list (Portuguese): [`doc/pt/ia/08-Plano-de-Recursos.md`](../../doc/pt/ia/08-Plano-de-Recursos.md) §7.
